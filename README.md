# 简化问卷系统

当前已实现账号、问卷管理、填写提交、统计结果和浏览器前端；第二阶段已新增独立题目资源、不可变版本、卷内保存关联、固定版本入卷、显式换版、指定版本共享、使用情况查询、个人题库分组与跨问卷题目统计的 API，并在 `/ui/` 前端接入这些操作。不包含未提交草稿自动保存或填写断点续填。浏览器打开 `/ui/` 使用前端，或打开 `/docs` 测试接口。

问卷的接口、字段示例、状态和跳转语义见 [问卷管理接口.md](问卷管理接口.md)。账号接口约定保持不变，见本文后续章节。

填写进度、答案校验、提交保存和幂等重试见 [填写模块接口.md](填写模块接口.md)。同一用户在同一问卷使用相同 `requestId` 和相同内容重试，返回原提交成功结果，包括问卷已关闭或截止后的重试。

整卷、单题统计及内容分页见 [统计结果接口.md](统计结果接口.md)。统计按成功提交份数计数，仅所有者可查看；每个响应使用同一个快照事务，内容按提交时间、提交 ID 升序排列，不返回填写者身份。

AI 协作的提示词摘录、代码产出、人工审定和使用说明见 [AI使用日志与说明.md](AI使用日志与说明.md)。

## 第二阶段：独立题目资源与版本

当前实现独立创建、本人列表、资源及版本读取、从任意历史版本派生、将旧版内容恢复为新版本，以及从卷内题保存、建立来源关联、固定版本选题入卷、草稿显式换版、指定用户/版本共享、按权限展示的使用查询、个人题库分组与跨问卷题目统计。第二阶段后端已完整；题库整体共享不在已审定范围。旧问卷展示、填写和卷内统计接口仍按第一阶段方式运行。第二阶段界面已在 `/ui/` 前端接入，也可使用 `/docs` 操作。

所有新接口要求 Bearer 登录，返回沿用 `{"code":0,"msg":"ok","data":...}`。资源列表、历史和向原资源派生/恢复仍仅限创建者；具体版本读取和使用可依据有效共享授权开放，并对接收者单独裁剪响应。版本内容包括 `title`、`type`、`options` 和 `validation`，不允许在 `validation` 中提供 `required`，也不包含卷内顺序和跳转。选择题创建时省略选项 ID，由服务端分配；派生时可沿用来源版本中**文本未改变**的选项 ID，新增或改名的选项需省略 ID。恢复复制旧版内容和选项 ID，但生成新的版本 ID，旧版不会改变。

| 操作 | 接口 | 请求体要点 |
| --- | --- | --- |
| 创建资源与初始版本 | `POST /question-resources` | `requestId`、题目版本内容 |
| 本人资源列表 | `GET /question-resources?page=1&page_size=20` | 仅返回本人资源 |
| 资源与版本历史 | `GET /question-resources/{resource_id}` | 返回版本序号、直接来源与创建方式 |
| 版本内容 | `GET /question-resources/{resource_id}/versions/{version_id}` | 返回该版本完整内容 |
| 派生版本 | `POST /question-resources/{resource_id}/versions` | `requestId`、`parent_version_id`、新版本内容 |
| 恢复旧版 | `POST /question-resources/{resource_id}/versions/{version_id}/restore` | `requestId` |

创建类操作按用户的 `requestId` 去重：相同标识、相同目标与内容返回原结果；同一用户复用标识执行其他题目操作返回 `4090`。资源、版本及去重记录同事务保存，需要 MongoDB 副本集；不使用填写提交的去重索引，也不修改原提交接口。

### 卷内保存与关联

只有问卷所有者能从卷内题保存独立资源或建立关联。`POST /surveys/{form_id}/questions/{question_id}/save` 提交 `{"requestId":"..."}`，只创建资源及初始版本，保留卷内题 ID、原题内容、答案和跳转，不建立关联；同一题使用新的 `requestId` 可以再保存一份。成功重试直接回放第一次事务读取到的题目快照，不重新读取后来编辑的卷内题。

`POST /surveys/{form_id}/questions/{question_id}/save-and-link` 提交 `{"requestId":"...","includeHistoricalAnswers":true}`，在一个事务中创建资源、版本并关联当前题。`POST /surveys/{form_id}/questions/{question_id}/link` 提交 `{"version_id":"...","includeHistoricalAnswers":true}`，将卷内题关联到本人或有效共享的内容完全一致的版本；同一关联重复请求在权限核验后返回原关联，改绑其他版本返回 `4090`。`GET /surveys/{form_id}/questions/{question_id}/source` 查询关联，未关联时 `data` 为 `null`。确认纳入历史回答只记录统计归属，跨卷统计接口已实现，见后文“跨问卷题目统计”。

已发布、手动关闭或已截止的旧题也可补关联，但不开放内容编辑。已关联草稿题的旧 `PATCH` 仍可修改跳转和卷内 `required`，版本级内容变动返回 `4090`；原 `validation` 仍是整体替换。仅改必答可用 `PATCH /surveys/{form_id}/questions/{question_id}/required`，请求体 `{"required":true}`，其他校验限制保持不变。关联与编辑、发布、关闭、提交通过问卷 `revision` 协调并发；关联单独存储在 `Question_links`，不修改已发布题内容或旧答卷。

本模块在隔离副本集上执行 `tests/test_question_links.py` 为 `16 passed`，另对资源版本及受影响的旧问卷、填写和统计接口做了定向回归；尚未重新运行全量测试。仍有原先的 Starlette/AnyIO 依赖弃用警告。

| 测试步骤 | 输入 | 预期输出 | 实际结果 |
| --- | --- | --- | --- |
| 保存后编辑原题，再重试首次请求 | 同一卷内题、同一 `requestId` | 返回第一次的资源与版本，内容仍为保存时快照 | 通过；不再读取当前题 |
| 关联已关闭或已截止的旧题 | 所有者及 `includeHistoricalAnswers: true` | 关联成功，旧问卷、答卷与旧统计保持不变 | 通过 |
| 修改关联草稿的必答设置和跳转 | `required` 及合法卷内跳转 | 卷内配置可改；版本级内容不变 | 通过 |
| 在关联创建过程中模拟写入失败 | 关联记录插入失败 | 资源、版本、去重记录和问卷 `revision` 一并回滚 | 通过 |

### 固定版本选题入卷

`POST /surveys/{form_id}/questions/from-version` 提交 `{"requestId":"import-age-v1","version_id":"具体版本ID","required":true}`。三个字段均必填，仅问卷所有者能选用本人或有效共享的具体版本，且首次执行时问卷必须为草稿。草稿截止时间已过仍可入卷，但发布前须调整截止时间。

入卷创建新的卷内题目 ID并追加到卷末，复制版本的题干、题型、选项（保留选项 ID）和校验限制，单独设置卷内 `required`，初始跳转为空。卷内题目与 `Question_links` 在同一事务中保存；资源之后新增版本不会自动更新入卷内容。成功响应沿用原响应包，`data` 包含卷内题目内容、`question_id`、`order`、`form_id`、`resource_id`、`version_id` 和关联信息。新题没有历史回答，关联不需要旧题补关联的确认参数。

同一具体版本在一份问卷中限一次，检查覆盖已有的卷内关联。同一资源的不同版本可以同时入卷，同一版本也可以进入不同问卷。不同请求再次选用同版本返回 `{"code":4090,"msg":"该版本已存在于当前问卷，不能重复入卷","data":{}}`，不附加已有题目 ID。不改动旧关联接口的重复规则，也不添加会拒绝历史重复关联数据的新唯一约束。

成功请求优先按用户和 `requestId` 回放首次结果，即使问卷后来发布或关闭也不重复添加；标识用于不同请求返回 `4090`。首次入卷与编辑、普通添加、发布通过问卷 `revision` 协调，且执行整卷校验；题目、关联、去重记录和 `revision` 一并提交或回滚。

入卷模块完成时只运行 `tests/test_version_import.py`（`19 passed`）及 6 项直接相关回归（`6 passed`），未运行全量测试。该记录早于下述草稿显式换版模块。

| 测试步骤 | 输入 | 预期输出 | 实际结果 |
| --- | --- | --- | --- |
| 选用具体版本入卷 | 版本 ID、`required` 和新请求标识 | 新卷内 ID，保留选项 ID，内容一致，跳转为空 | 通过，覆盖四类题型 |
| 创建新版后读取原卷，再选新版入卷 | 同一资源的两个版本 | 原题不变，两版以不同卷内 ID 共存 | 通过 |
| 并发重试或不同请求选同版本 | 相同或不同 `requestId` | 同请求返回同结果，不同请求仅一个成功，其余 `4090` | 通过 |
| 模拟关联写入失败后重试 | 关联插入失败、原请求标识 | 无半完成题目或去重记录，`revision` 回滚，重试可成功 | 通过 |
| 入卷与手动添加、编辑、发布竞争 | 并发操作 | 顺序唯一，发布内容一致，无部分写入 | 通过 |

### 草稿显式换版

仅问卷所有者可对已关联的草稿题换版，且仅限同一资源内的版本。切换目标可为本人或有效共享版本；切当前版属于既有引用核验，撤销后仍可返回 `changed: false`。向原资源派生并换版仍仅限原资源所有者。保留卷内题目 ID、顺序、`required` 和原跳转，替换版本级内容及关联版本 ID；不自动重映射选项 ID或清空跳转。先核验当前副本与原关联一致，再对候选内容校验整卷。目标版被本卷其他题使用时返回 `4090`，错误 `data` 保持 `{}`。

| 操作 | 接口 | 请求体 |
| --- | --- | --- |
| 切换已有版本 | `POST /surveys/{form_id}/questions/{question_id}/switch-version` | `requestId`、`expected_version_id`、`version_id` |
| 派生新版本并切换 | `POST /surveys/{form_id}/questions/{question_id}/derive-and-switch` | `requestId`、`expected_version_id`、`parent_version_id`、完整版本内容 |

首次执行要求 `expected_version_id` 与当前关联相同，否则返回 `4090`；父版本可为同资源任意历史版本。不接受 `required` 或跳转修改参数，必答和跳转仍通过原卷内配置接口调整。成功返回换版后的题目及关联信息和 `changed`；目标正是当前版时返回 `changed: false`，不改题目或关联记录，但整卷核验及问卷 `revision` 协调、成功去重记录仍完成。

成功请求优先回放首次结果快照，因此发布、关闭后仍可重试，或题目后来又换版时重试原请求；重试不会再次修改关联。新的换版请求仍仅允许草稿。切换已有版失败不撤销原先独立创建的版本；派生并切换失败则新版本、版本序号、题目、关联、问卷 `revision` 和去重记录全部回滚。关联的 `linked_at` 保留首次建立关系的时间。

本轮在隔离副本集上运行换版模块测试 `21 passed`，运行独立资源版本及直接相关入卷、编辑回归 `28 passed`；未运行全量测试。仍有原有的 Starlette/AnyIO 依赖弃用警告，前端未接入换版功能。

| 测试步骤 | 输入 | 预期输出 | 实际结果 |
| --- | --- | --- | --- |
| 同资源切换已有版 | 预期原版本 ID、目标版本 ID | ID、顺序、必答和跳转不变，内容与关联更新 | 通过，覆盖四类题型 |
| 换到删除原跳转选项的版本 | 原跳转、缺少该选项的目标版 | 整卷校验失败，无部分修改，已有版仍保留 | 通过 |
| 创建新版并换版失败 | 不合法跳转或模拟关联更新失败 | 新版本、序号、卷内记录、`revision` 与去重一起回滚 | 通过 |
| 不同请求基于同一旧版并发换版 | 相同 `expected_version_id` | 仅一方成功，另一方 `4090`，不覆盖成功结果 | 通过 |
| 换版后再换回并发布关闭，再重试首次请求 | 首次原请求体与 `requestId` | 返回首次快照，不重新读取或修改当前关联 | 通过 |

### 指定用户与版本共享

详细请求、响应、权限矩阵、集合字段与四部分测试摘要见 [题目共享接口.md](题目共享接口.md)。

| 操作 | 接口 | 请求体要点 |
| --- | --- | --- |
| 授权共享 | `POST /question-resources/{resource_id}/versions/{version_id}/shares` | `requestId`、`recipient_username`，完整用户名匹配 |
| 已发出的授权 | `GET …/versions/{version_id}/shares` | 所有者分页查询，含已撤销记录 |
| 撤销授权 | `POST …/versions/{version_id}/shares/{share_id}/revoke` | `requestId` |
| 收到的共享 | `GET /question-shares/received` | 当前有效授权，按最近真正授权时间分页 |
| 独立派生资源 | `POST …/versions/{version_id}/fork` | `requestId`、版本内容，新资源归调用者所有 |

接收者具体版本读取仅返回 ID、版本号、时间和内容，不返回未授权历史或原问卷来源。共享不能修改原资源或访问他人问卷/答卷统计。授权记录复用，授权修订号与使用协调计数分开；首次无有效授权为 `4030`，本次调用已绑定有效授权但期间改变为 `4090`，事务自动重试及唯一键重试不改绑新授权。

真正撤销或重新启用才更新对应时间与授权修订号；无变化操作只保存去重结果。成功回放中的 `status` 和修订号是首次操作的历史结果，不代表当前状态，客户端须重新查询授权列表。

撤销不收回已有内容。既有副本可继续编辑卷内配置、发布和填写；可通过 `save` 保存为自己的独立资源，再分享该资源。`fork` 及已关联副本保存的新初始版本记录 `source_resource_id`、`source_version_id`；来源不授予上游权限，也不回写旧版本。

### 题目使用情况查询

详细输出、计数、权限、聚合投影与测试见 [题目使用查询接口.md](题目使用查询接口.md)。

- `GET /question-resources/{resource_id}/usage`：仅资源所有者，返回本人问卷明细及他人去重汇总数量。
- `GET /question-resources/{resource_id}/versions/{version_id}/usage`：所有者同上；有效授权接收者或有本人既有有效引用者，只返回本人使用，不返回他人数量或版本内容。

两者均支持 `page/page_size`，按问卷分页。仅当前有效来源关联计使用，资源/版本分别按问卷去重；资源总数不能相加版本数量得到。共享、仅保存、fork 来源不算使用，不查询答卷。撤销后仍可管理本人既有引用，不恢复原内容读取权限。

他人汇总数量是明确允许的有限信息披露，不附带用户、问卷、状态或时间分组。本人明细用白名单输出；连接后尽早投影版本归属、问卷和题目必要字段，接收者不执行他人汇总。

空结果为数量 0 和列表 `[]`，越界页只清空列表，保留真实 `total`；题目按 `order`、`_id` 升序，问卷按创建时间、`_id` 倒序。权限、数量和列表使用同一只读快照，不写业务集合。原登录会话成功续期保持不变。

使用查询模块完成时专项 `32 passed`；资源/关联/入卷/换版/共享及静态入口直接相关回归 `124 passed`。未运行全量，未操作业务实例，原依赖弃用警告仍在。没有新增删题 API；移除及异常旧数据仅在随机测试库模拟。随后完成的个人题库见下一节。

### 个人题库分组

完整输入、响应、权限、事务和四部分测试摘要见 [题库分组接口.md](题库分组接口.md)。题库仅个人管理，不支持整体共享；题目继续按具体版本授权。

- `/question-banks` 提供创建、本人列表；`/{bank_id}` 提供详情和 PATCH 名称/说明。
- `/{bank_id}/members` 提供列表、收录；`/{member_id}/switch-version` 显式更新，`/{member_id}/remove` 移出；`/{bank_id}/delete` 删除题库。写操作均带 `requestId`，成员接口位于 `/{bank_id}/members` 下。
- 同资源在单题库一条成员并固定版本，多题库可以各自指定不同版本。新请求重复同版仍检查权限，返回 `changed: false`；不同版要求显式更新。历史成功回放不受后来撤销或删除影响。
- 名称先去首尾空白再校验 1–100 字符，不唯一；说明保留原文，最多 1000 字符，允许空字符串清空。PATCH 至少提供一个修改字段，不接受 null。
- 成员列表按收录时间/ID 倒序，更新不重排；不可用或资源归属异常成员仍计总数，但不返回题干/题型。空/越界页计数保持正确。
- 移出、删除仅需题库所有权，不要求原授权；允许不可用旧版更新至同资源可用目标。成员关系不授予任何版本权限。

`POST /surveys/{form_id}/questions/from-bank` 必填 `requestId`、`bank_id`、`member_id`、`expected_member_version_id`、`required`。首次入卷在同事务核验预期成员版本、目标授权及草稿，协调题库和问卷 revision；成员已经从 v1 更新为 v2 时，不替用户改选 v2。成功重试回放首次题目快照，不解析当前成员。

## 数据与安全

### Users

`_id`、`username`、`password_hash`、`created_at`。

- `username` 去除首尾空白后为 1-50 个字符，允许中文，区分大小写，建立唯一索引。
- 密码不去除首尾空格；缺失、`null`、空字符串及纯空白密码均视为空。注册时长度为 6-12 个 Python 字符，不是 UTF-8 字节数。
- 密码使用 Argon2id 加盐哈希，不存明文，不返回哈希。
- 并发注册同名账号时，由唯一索引保证只有一次注册成功。

### Sessions

`_id`、`user_id`、`token_hash`、`created_at`、`expires_at`。

- 使用 32 字节安全随机数生成 URL-safe 凭证；只返回凭证原文，不写入数据库或日志。
- MongoDB 仅保存凭证 SHA-256 哈希。随机凭证具有高熵，不使用用户密码式的低熵输入。
- `user_id` 唯一索引保证单账号只有一条会话；登录原子替换凭证，新凭证生效时旧凭证失效。并发登录以最后完成的数据库写入为准，不以客户端收到响应的先后为准。
- `token_hash` 有唯一索引；`expires_at` 有 TTL 索引。鉴权仍显式检查过期时间，不依赖延迟执行的 TTL 删除。
- 所有时间按 UTC 保存为 BSON Date；接口时间使用带时区的 ISO 8601 字符串。
- 登录成功后有效期为 72 小时。需认证接口在认证通过且业务成功（HTTP 2xx 且 `code = 0`）后，更新为当前时间加 72 小时；失败和公开接口不续期。
- 退出删除当前会话，不续期。重复退出、被顶替的凭证、无效或过期凭证统一视为未登录。
- 续期使用带凭证哈希和未过期条件的 `$max` 更新，不使用 `upsert`，不会缩短期限或恢复已退出、已被替换的会话。
- 已通过认证的在途请求可能在退出或新登录后完成，但无法续期旧凭证。撤销登录不会中断正在执行的业务操作。

注册和登录属于公开接口，登录不会自动复用客户端传入的旧凭证。凭证属于 Bearer 凭证，持有者即可使用；部署到非本机环境时必须使用 HTTPS，并避免在 URL 中传递凭证。本模块未扩展验证码、登录限流或找回密码。

## API

成功和失败均使用 `{"code": ..., "msg": "...", "data": {...}}`；HTTP 状态码与业务错误码不同，前端应分别读取。

### POST /auth/register

公开接口，JSON 请求体：

```json
{"username":"alice","password":"secret"}
```

成功为 HTTP 200：

```json
{"code":0,"msg":"ok","data":{"user_id":"MongoDB ObjectId 字符串","created_at":"2026-10-17T12:00:00+00:00"}}
```

### POST /auth/login

公开接口，请求体与注册相同。登录不重复限制密码长度，只检查非空和字符串类型，再验证密码。

成功为 HTTP 200：

```json
{"code":0,"msg":"ok","data":{"token":"随机凭证","username":"alice"}}
```

之后访问需认证接口时设置：

```text
Authorization: Bearer <token>
```

在 `/docs` 中可点击 `Authorize`，只填写 token 值。

### POST /auth/logout

无需请求体，必须携带以上请求头。成功为 HTTP 200：

```json
{"code":0,"msg":"退出成功","data":{}}
```

### 失败响应

参数校验先于数据库查询和密码认证执行，因此漏填不会返回 `4011`。

| 情况 | HTTP | code | msg |
| --- | --- | --- | --- |
| 用户名或密码缺失、null、空字符串、纯空白 | 400 | 4001 | 用户名/密码不能为空 |
| 用户名或密码不是字符串 | 400 | 4001 | 用户名/密码必须为字符串 |
| 去除首尾空白后的用户名超过 50 个字符 | 400 | 4001 | 用户名长度应为 1–50 个字符 |
| 注册密码长度不在 6-12 个字符 | 400 | 4001 | 密码长度应为 6-12 个字符 |
| JSON 语法错误 | 400 | 4001 | 请求体必须是有效的 JSON |
| 请求体不是 JSON 对象 | 400 | 4001 | 请求体必须是 JSON 对象 |
| 用户名已占用 | 409 | 4090 | 该用户名已被注册 |
| 登录用户名不存在或密码错误 | 401 | 4011 | 用户名或密码错误 |
| 需登录接口的凭证缺失或失效 | 401 | 4010 | 请先登录 |
| 不存在的路径 | 404 | 4040 | 不存在 |
| 请求方法错误 | 405 | 4001 | 请求方法不允许 |
| 运行中数据库故障 | 503 | 5000 | 服务暂不可用，请稍后重试 |
| 未预期内部异常 | 500 | 5000 | 服务器内部错误 |

`4030` 用于问卷管理和统计等接口的所有者权限检查。`5000` 仅用于基础设施或内部异常，避免误报成用户参数错误；错误响应不包含密码、凭证、堆栈和数据库连接详情。

## 后续接口如何复用认证

后续需认证的 JSON 接口，使用 `AuthenticatedRoute` 路由类和 `require_user` 依赖；前者负责成功后续期，后者返回 MongoDB 用户 ID：

```python
from fastapi import APIRouter, Depends
from app.auth import AuthenticatedRoute, require_user
from app.errors import success

router = APIRouter(route_class=AuthenticatedRoute)

@router.get("/example")
def example(user_id=Depends(require_user)):
    return success({"user_id": str(user_id)})
```

示例没有注册进当前应用。只有 `require_user` 而没有 `AuthenticatedRoute` 时只认证、不续期。流式响应不在当前统一 JSON 响应约定内。

填写模块使用 `Responses` 保存完成的提交，新增请求标识、内容摘要、匿名及次数限制标记；部分唯一索引兼容缺少新字段的旧记录。每次新提交会更新问卷内部 `revision` 来协调关闭竞争，但不改变已发布内容。

统计模块只读 `Question_forms`、`Questions`、`Responses`，不建立统计缓存或改写旧答卷。新增普通索引 `form_question_oldest` 支持题目过滤和内容排序。文本、数字明细通过单题接口分页查看全部；不论问卷是否匿名，统计接口都不返回填写者身份。实名答卷明细由问卷管理模块的 `GET /surveys/{form_id}/responses` 只读提供，按问卷匿名设置隐藏匿名填写者身份，只返回白名单字段。
